feat(core): entity runtime + full movement chain (#7)

M2-T1 tracer bullet (ADR-0028, spec/03 §7, spec/04 §1):

- Entity interface + createEntity: the eight movement-family hooks
  (at_pre_move / announce_move_from / announce_move_to / at_post_move +
  container-side at_pre_object_leave / at_pre_object_receive /
  at_object_leave / at_object_receive), designed for any entity; engine
  defaults are the two announces — one semantic event (departed/arrived)
  per receiver, mover included, never render-then-broadcast (B5).
- MOVE_TYPES five-value enum (teleport/traverse/get/give/drop) carried in
  MoveInfo into every hook.
- moveTo: pure hook orchestration (all veto points precede all
  announcements) + the move's single position write, ZERO permission
  checks; locations may be room ids or entity ids (containers).
- WorldRuntime: ContentRegistry + the one state tree (state/tree.ts seed:
  EntityState {id, locationId, flags}) + hook-carrying instances;
  occupantsOf ascending (deterministic); subjectOf answers gates from
  tree state.
- traversalSpec, the engine-factory traversal adapter: exit traverse gate
  (pipeline access stage) -> target room enter gate (checkAccess, refusal
  event carries roomId) -> moveTo("traverse"); both gate refusals are
  rejected + commandRefused semantics, copy stays in content JSON.
- Pipeline: execution-stage rejection channel (func may return
  CommandRejection — the refusing executor words its own refusal event;
  at_post_cmd skipped) and ctx.predicates; harness liveWorld mode for
  driving a runtime across a session.
- Tests: entity-move.test.ts (hook order, three veto points, zero gates,
  per-receiver, tree, loud failures) + traversal-chain.test.ts (full
  Liuqing town chain over real content, second fake player multi-receiver,
  far player hears nothing, both gates' rejection copy from JSON,
  deterministic replay). engine-purity stays green.
