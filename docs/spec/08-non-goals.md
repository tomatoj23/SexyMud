# 08 · 明确不做的事

> **本目录最重要的一份。** 五轮调研（25 个子代理）最有价值的结论，**一半是"不要做什么"**。这些散落在 8 个 ADR 的 "Considered Options" 里，极易被"要做什么"淹没而重复踩坑。
> **每次做设计决策前，先读这份。**

## A. 架构层面：不做的事

### A1. 不做 attribute handler
Evennia 那一千多行（`_cache`/`_catcache`/`SaverMutable` 代理/后端抽象）**是在为 SQL ↔ Python 的阻抗失配买单**：隐藏 SQL、隐藏 pickle、惰性加载、可替换后端、嵌套可变体原地写回。我们四项都没有（内存 JSON 快照、原生 JSON 值、整体驻留、无 DB）。
**替代**：typed 状态对象 + 版本化迁移链 + 加载时倒排索引 + 薄访问门面。见 `04-state-and-time.md`。
**依据**：ADR-0025 §二

### A2. 不做 Typeclasses（代码即类型）
用 Python 类表达实体类型，与「全部数据为 JSON」直接对立。
**替代**：JSON 的 `type` 字段 + 行为/hook 注册表。
**依据**：ADR-0022 记录

### A3. 不做 protfuncs / 内联脚本（`$func()`）
无法被 JSON Schema 校验，且是通往软编码失控的路。Evennia 的 `protfuncs` 里就有 `$random()`——**违反确定性**。
**替代**：显式白名单求值节点 + 引擎注入的种子化 RNG。
**依据**：ADR-0022 §3、ADR-0023 记录

### A4. 不执行任意代码来构建世界（Batch-Code Processor）
Evennia 的批处理有执行裸 Python 的模式，源码自带安全警告。
**替代**：只取 Batch-Command 的「顺序构建 + 可重放」思想，具体形态是 JSON + Schema。
**依据**：ADR-0022 记录

### A5. 不做 async / 线程 / 每对象定时器
与「引擎完全确定性」矛盾。
**替代**：调度六原语（Clock / 纯 stage 求值 / 观察时补偿结算 / 到期桶 / 区域 tick / on-change）。见 `04-state-and-time.md`。
**依据**：ADR-0022 §5、ADR-0025 §三

### A6. 不用对象标识做缓存键
Evennia 的 `_CMDSET_MERGE_CACHE` 用 `id(cset)` 做键且**无失效逻辑**，对象回收后 id 复用会返回陈旧结果。
**替代**：内容哈希 + 显式失效。
**依据**：ADR-0024 §2

### A7. 现在不做插件系统（YAGNI）
扩展靠**六条契约**（见 `01-engine-contract.md` §7），**不靠插件加载器**。

**理由**：
1. 目前只有一套内容包（武侠）。为假想的第二套游戏设计插件系统是**最典型的过度设计**。
2. **模块边界需要真的实现过才知道**。「战斗」和「技能」该不该分开？答案只在写过一遍之后才靠谱。现在连第一个机制都还没有，设计机制间的插件接口是纯猜测。
3. **边界定错比不做更痛**。插件间会形成隐式依赖网，改起来比单体难受得多（Eclipse／OSGi 的教训）。

**什么时候做**：当第二套内容包需要复用内核时，把已实现的机制**抽**成模块。那时边界已知——**抽取是重构，不是设计**。

> 这就是「**先做对，再拆开**」，而不是「先拆开，再填」。

**对照 Evennia**：它不做战斗进核心（因为它要覆盖任意游戏），也不做插件加载器（它用 `game_template/world/` 目录约定）。它的可扩展性来自**分层 + 约定**，不是插件框架。

**依据**：本次架构讨论（2026-09-01）

## B. 交互层面：不做的事

### B1. 不做模态分页（EvMore 式）
Evennia 的 EvMore 用 `Replace` 合并命令集**劫持输入**来翻页，是模态的。战斗输出是**追加式滚动流**，劫持输入会打断它。
**替代**：只取「按显示高度切块 + 边界感知」，分页/滚动是客户端职责。
**证据**：EvAdventure（完整示例游戏）**大半开发量花在绕开 EvMenu 的模态性**——手写状态机模拟多步输入、跨玩家强关对方菜单、把 `ndb` 当临时缓存。整个游戏只新增 5 条命令。
**依据**：ADR-0023 §7、ADR-0025 记录

### B2. 不做「菜单即主交互」
同上。对话/奇遇/任务链用**节点图**（`{文本, 选项[]}`，`goto` 指向节点名或具名 effect），且**内容只被 parse，不被 eval**。
**依据**：ADR-0023 §6

### B3. 不做终端仿真（ANSI → HTML）
Evennia 的双转换管线（服务端 `parse_html` + 客户端 `parse2html` 带状态机）是**为兼容 1980 年代哑终端付的税**。
**替代**：引擎发结构化 token（语义样式名），各端映射到原生渲染。
**依据**：ADR-0018、ADR-0025 记录

### B4. 不在引擎内渲染文本
`GameEvent` 必须是**纯语义 JSON**（谁、对谁、做了什么、结果档位），渲染推迟到 `TerminalView`。Evennia 在线上传输已渲染字符串，是它最贵的历史包袱。
**依据**：ADR-0006、ADR-0025 §一.3

### B5. 不做「先渲染成字符串再群发」
若这样做，中文的「你／他／她／它」与按观者的可见性差异**永远补不回来**。
**替代**：渲染是纯函数 `(event, observerState) => string`，**按接收者逐一遍历**。
**依据**：ADR-0023 §2、ADR-0025 §五.3

## C. 内容层面：不做的事

### C1. 不把题材词放进引擎
**由 `engine-purity` 测试强制**（已实现，会真实报错）。CONTEXT.md 是**武侠内容包**的术语表，不是引擎词汇表。
**依据**：硬标准 1、ADR-0004、ADR-0026

### C2. 不硬编码任何数量
境界数量、门派数量、槽数、阈值——全部来自内容。引擎只遍历。
**依据**：硬标准 1、ADR-0004

### C3. 不用 `null` 表示「无限」
Evennia 用 `None` / `0` / 负数**三种方式**表示无限，极不一致。
**替代**：显式 `{"unlimited": true}`。
**依据**：ADR-0025 记录

### C4. 不做模块路径 / typeclass / cmdset 进 settings
那是「装配图」（STRUCTURE），改它等于改代码。
**替代**：配置三分法——STRUCTURE（不进 settings，用 `$ref` 指向内容）／TUNING（数字，进 `settings.json`）／POLICY（决策，另开 `policy.json`）。
**依据**：ADR-0025 记录

### C5. 不在 tag 上带值
Evennia 的 tag `data` 字段是**全局的、最后写入者赢**（因为 data 不参与唯一性约束）。
**替代**：需要带值就用属性。
**依据**：ADR-0025 §二

### C6. 不做目录分层表达内容归属
**替代**：归属字段化（`zoneId` / `sectId` / `regionId`）+ 标签。
**依据**：ADR-0008、ADR-0021 §5

## D. 中文层面：不做的事

### D1. 不做分词
Evennia 的解析器按空格分词，中文没有空格。但**解法不是引入分词库**——MUD 命令的语法空间是受限的。
**替代**：**最长动词匹配**（别名按长度降序，防子串冲突）+ 参数形态由命令条目声明。
**依据**：ADR-0024 §1

### D2. 不抄 Evennia 的 CJK 处理
它只有 24 行 `display_len()`（W/F 记 2，其余记 1），**不处理**组合符（应记 0）／emoji／控制字符，且**几乎没被调用**。
**替代**：自研显示宽度函数，并**必须注入切块器本身**（Evennia 正是漏了这一步）。
**依据**：ADR-0023 §4、ADR-0024 §4

### D3. 不做动词变位
中文无动词变位，不需要 Evennia 的 `$conj()`。只需处理**人称代词**。
**依据**：ADR-0021 §3

### D4. 不强制拉丁化角色名
Evennia 的 `normalize_name` 是反例，源码自己承认「should be refactored to support i18n for non-latin names」。
**依据**：ADR-0025 §五

### D5. 不用黑名单过滤玩家输入
**替代**：解析前转义 + 白名单重建；引擎 markup 使用**玩家无法产生的私有码位**，让「不可混淆」成为**构造性保证**而非正则兜底。
**依据**：ADR-0025 §八

## E. 反面清单：看到这种写法就是错的

| 写法 | 为什么错 |
|---|---|
| 引擎源码里出现「秘境」「造诣」「门派」「练功」 | 硬标准 1，纯度测试会报错 |
| 引擎 `import` 了 `content/` 下的 JSON | 必须经 `ContentRegistry` |
| 命令里没有 `actorId` | 最贵的 retrofit（ADR-0025 §一） |
| `GameEvent` 里含已渲染的中文文本 | 渲染推迟到边界外（ADR-0025 §一.3） |
| 用 `Date.now()` / `Math.random()` / `setTimeout` | 违反确定性（ADR-0017） |
| 给每个对象挂定时器 | 用调度六原语（ADR-0025 §三） |
| 先渲染字符串再群发 | 中文代词永远补不回来（ADR-0025 §五.3） |
| 输入队列用 `pop()` | 从尾部取，顺序反了（Evennia 的真实 bug） |
| `at_pre_cmd` 返回真值静默跳过整段 | 测试会绿着通过却什么都没执行 |
| 用 `null` 表示「无限」 | 三种不一致约定（C3） |
| 无条件正则剥离输出文本的装饰行 | 会吃掉以 `| `／`--`／`+` 开头的中文正文 |
| 缓存键用对象引用/`id()` | 标识复用返回陈旧结果（A6） |
| `if start < end` 判断时间区间 | 跨年区间永不匹配（Evennia 的真实 bug） |
| 引入分词库处理命令 | 受限语法空间不需要（D1） |
