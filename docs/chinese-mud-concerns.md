# 中文 MUD 特有问题全景

> **定位**：设计研究清单，**不是 ADR**（不含决策，只列问题与对策）。它是「中文优先引擎」这条产品定位的**需求来源**。
> **来源**：五轮 Evennia 调研、`docs/research/xkx100-*.md`（侠客行一百，原生中文 MUD 的一手资料）、以及本项目 ADR-0021/0023/0024/0025 中已定的对策。
> **用法**：每新增一个子系统，先来这里对照——有没有踩到中文特有的坑。

## 为什么需要这份清单

英文 MUD 框架的几乎每一个文本假设，在中文下都不成立：

| 假设 | 英文 MUD | 中文现实 |
|---|---|---|
| 词之间有分隔符 | 空格分词 | **无空格** |
| 一个字符占一列 | 成立 | **全角占两列**，组合符占零列 |
| 动词随主语变位 | 必须处理（`$conj`） | **不变位**，但人称代词要换 |
| 标点 | 半角 | **全角**，且有避头尾规则 |
| 排序与检索 | 字母序 | **拼音序 / 笔画序 / 子串 + 拼音首字母** |

Evennia 是一个成熟的现代 MUD 框架，但它的 CJK 支持**只有 24 行**（`utils.display_len()`），而且**几乎没有被调用**——`evmore`／`ansi`／`text2html`／`evmenu` 全都没用它。这不是疏忽，是它的设计假设里没有中文。**这就是我们的机会。**

## A. 输入层

| # | 问题 | 对策 | 出处 |
|---|---|---|---|
| A1 | **中文无空格**，英文那套分词 + `switch/lhs/rhs` 解析完全失效 | **最长动词匹配**：从输入串开头匹配最长的已注册动词，余下整体作参数串。**不引入分词库** | ADR-0024 §1 |
| A2 | 子串冲突（「笑」吃掉「笑傲江湖」） | 别名按**长度降序**匹配（长优先），并要求 schema 校验能覆盖 | ADR-0024 §1 |
| A3 | 中文输入法成本高，移动端尤甚 | 命令别名**双层**（内容层全局 + 玩家层 nicks）、补全、历史、常用命令快捷条 | ADR-0021 §4、ADR-0018 |
| A4 | 中英混排输入（玩家可能输 `n`／`北`／`north`） | 同一命令的 `verbs[]` 里中文与英文缩写并列 | ADR-0021 §2 |
| A5 | 英文用 `name-N` 后缀消歧（Evennia 的 docstring 还写错了成 `2-ball`） | 中文改用「第 N 个 X」／「X·N」形式，作为 `argForm` 的取值枚举 | ADR-0024 §1 |
| A6 | 全角／半角标点混输（`，` vs `,`） | 🚧 **待定**：建议输入归一化（全角标点 → 半角），但需先确认是否影响中文标点在命令中的语义 | — |
| A7 | 中文量词与数量表达（「两个山贼」「一柄剑」） | 解析层只切动词与参数串，量词交给命令条目的 `argForm` 处理 | ADR-0024 §1 |

## B. 输出与渲染层

| # | 问题 | 对策 | 出处 |
|---|---|---|---|
| B1 | **CJK 显示宽度**：全角 = 2 | 自研 `wcwidth` 式函数 | ADR-0023 §4 |
| B2 | 组合符／变体选择符应记 **0** 列，emoji ZWJ 序列、控制字符 | 同上，需显式覆盖（Evennia 的 `display_len` 只处理 W/F） | ADR-0024 §4 |
| B3 | 宽度函数写了却没用上（**Evennia 的真实教训**） | **必须注入切块器本身**，不能只在别处调用 | ADR-0024 §4 |
| B4 | 分块会切断未闭合的样式 span | 维护 token 数组 + 平行「可见字符索引」；切块时反查 `(tokenIndex, intraOffset)`，并在首尾**重开／补闭合** span | ADR-0024 §5 |
| B5 | 中文无动词变位（比英文简单） | 不需要 `$conj()` 那套；只做**人称代词**替换 | ADR-0021 §3 |
| B6 | 人称代词：你／我／他／她／它／您／咱们，且随观察者变化 | 渲染做成**纯函数** `(event, observerState) => string`，按接收者逐一遍历 | ADR-0023 §2、ADR-0025 §五 |
| B7 | **按接收者逐一渲染**是硬要求 | 若做成「先渲染成字符串再群发」，中文的「你／他／她／它」与按观者的可见性差异**永远补不回来** | ADR-0025 §五.3 |
| B8 | 全角标点的**避头尾**规则（行首不能出现 `。，、！？`） | 🚧 **待定，但已绑定触发点**：**写折行器时必须一次做对**——已列入 `docs/spec/05-output-pipeline.md` §10 自检清单。理由：避头尾是折行器的内在约束，先做「简单折行」再打后处理补丁，等于重写折行器核心 | spec/05 §10 |
| B9 | 中英混排是否加空格（「使用 白虹贯日」） | 🚧 **待定**：内容层约定，写进 `content/style-guide.md` | — |
| B10 | 武侠文本的中文字体表现（衬线、墨色） | 已定：叙事层主体用**衬线 + 墨色** | ADR-0006 |

## C. 叙事文本生成（中文特有，也是 xkx100 的金矿）

| # | 问题 | 对策 | 出处 |
|---|---|---|---|
| C1 | 战斗文本需要「伤害越大越夸张」的可感知梯度 | xkx100 的**伤害分档文案矩阵**：同一结构 + 程度递进，最后档必带双感叹号 | ADR-0011、xkx100 §6.2 |
| C2 | 造诣的中文表达 | **50 档**区间表（xkx100 §5.1），由数值推导，纯显示不设门槛 | ADR-0019、CONTEXT |
| C3 | 受击部位 | xkx100 的人类 **21 个部位**表 | xkx100 §6.7 |
| C4 | 中文量词（一柄剑／一把刀／一支笔） | 物品条目自带 `unit` 字段（xkx100 的做法） | xkx100 §4.1 |
| C5 | 四字格与节奏感 | 🚧 **待定**：`content/style-guide.md` 目前**没有**四字格条款（只有语体、1~3 句、句式雷同约束）。要么补写条款，要么降级为内容层自由裁量 | — |
| C6 | 称谓体系（后生 → 少侠 → 前辈） | NPC 敬称随**造诣档位**变化，是内容表条目 | ADR-0020 §4 |
| C7 | 招式名的括注符号 | 用「」而非英文引号 | style-guide |
| C8 | 数值→文本的映射散落各处 | 统一为**区间表 → 中文词**，引擎不给默认文案 | ADR-0023 §3 |

## D. 检索、排序与图鉴

| # | 问题 | 对策 | 出处 |
|---|---|---|---|
| D1 | 中文排序（拼音序 vs 笔画序） | ✅ **定拼音序**：与 D2 的「拼音首字母索引」**口径一致**——检索与排序用同一套认知，玩家不会困惑；`Intl.Collator('zh-Hans-CN')` 零依赖；笔画序需几千字笔画表且正确性难验证。⚠️ **`Intl` 的结果跨环境不保证一致**（Node 的 ICU 版本 vs 浏览器可能不同），故**仅限呈现层**——不得用于引擎决策、不得进存档。将来若排序结果要影响游戏逻辑（如服务端算排行榜名次），须换成自带的确定性拼音表 | 本清单 |
| D2 | 中文模糊检索：Lunr 等对中文不友好 | **子串匹配 + 拼音首字母索引** | ADR-0022 记录 |
| D3 | 帮助／图鉴的子主题层级 | 采用 xkx100 的**命名前缀分族**（`newbie-shaolin` / `ms_*` 一类）。⚠️ 斜杠子主题语法（`help 少林/罗汉拳`）是**本清单的引申，非 xkx100 原文**——原文只有前缀分族 | xkx100 §6（引申） |
| D4 | 中文分词在**命令匹配**里不需要，但在**模糊命令建议**里可能需要 | 🚧 **待定**：建议先用「编辑距离 + 子串」，不做分词 | — |

## E. 存档、编码与标识

| # | 问题 | 对策 | 出处 |
|---|---|---|---|
| E1 | 中文角色名 | **不能强制拉丁化**——Evennia 的 `normalize_name` 是反例，它自己承认该重构以支持非拉丁名 | ADR-0025 §五 |
| E2 | 内容 id 仍用 ASCII，显示名用中文 | 已有规则（`content.md` id 规则） | content.md |
| E3 | UTF-8 全链路（JSON、存档、输出） | ✅ **已实现**：`packages/core/tests/migrations.test.ts` 的「survives a full serialization roundtrip losslessly, including CJK」断言 `revived.label === "少侠"` | ADR-0026 |

## F. 引擎的中立性（中文引擎 ≠ 武侠引擎）

| # | 问题 | 对策 | 出处 |
|---|---|---|---|
| F1 | 引擎里不能有任何题材词 | 引擎纯度测试（已实现，会真实报错） | 硬标准 1、ADR-0004 |
| F2 | 中文支持属于**引擎层**，武侠术语属于**内容层** | 本清单 A–E 全部属于引擎；C1–C7 的具体词库属于内容 | — |
| F3 | 验收：换一套非武侠内容，引擎不改一行代码 | 见 ADR-0026 | ADR-0026 |

## G. 补充条目（2026-09-01 全量审计新增）

| # | 问题 | 理由 | 归属 |
|---|---|---|---|
| **G1** | **中文数词参数**（一／二／十／两／半） | A7 只交了量词没交数词；最长动词匹配切完余串后，剩下的仍是中文数字 | engine（解析）+ content（词表） |
| **G2** | **中文角色名的重名与视觉混淆**（同形字、全角空格、零宽字符冒充） | ADR-0025 §五 已点出「重名检查要另做」；E1 只写了「不强制拉丁化」 | engine |
| **G3** | **IME 合成事件**：React 在 `composition` 中按 Enter 会提交半成品拼音 | 中文输入最高频的真实缺陷；`apps/web` 目前是占位壳，正是写入窗口 | host (web) |
| **G4** | **中文字体栈／字重／行高**：中文字体无真 bold（伪粗体糊）、`line-height` 与标点挤压 | B10 只定了「衬线 + 墨色」，无可落地约束 | host |
| **G5** | **简繁体**：玩家繁体输入、古籍内容繁体别名，是否做简繁归一化 | 全清单此前零覆盖，且直接影响别名匹配 | content（别名）+ engine（是否归一化） |
| **G6** | **宿主存档编码**：`LocalSaveStore` 的 localStorage 往返未测（E3 只测了 core 纯 JSON） | E3 的缺口；WebView 下 surrogate pair 有真实风险 | host |
| **G7** | **中文进 URL／路由**：图鉴深链若用中文显示名会污染路由 | E2 只约束了 id，没约束深链 | host |
| **G8** | **竖排** | 武侠题材迟早被提出，越早否掉越省 | host / content（**建议列入 non-goals「不做竖排」**） |

> G1 与 A7 是同一条链上的空洞，建议合并处理。A6 的全角标点归一化还涉及**别名与检索两侧的不对称**（内容 `verbs` 用半角、玩家输全角）——归一化点应在「动词匹配前」，不是全局 strip。
