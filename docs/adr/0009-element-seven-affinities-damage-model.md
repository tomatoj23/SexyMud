# 元素（七系）与内外功伤害模型：兵刃层 + 系别层，方式 × 性质正交，玩家抗性走条件修饰符

> ⚠️ **2026-09-01 更新**
> - 标题里的「元素」是旧称，CONTEXT.md 已定名为**系别**（`_Avoid_: 元素）；系别的**表现力**另见 **ADR-0020**（改用结构签名而非系数）。
> - 文中 `BRIEF §12.4`、`BRIEF §11.2` 两处引用指向的 `docs/design-spec-BRIEF.md` **已于 2026-09-01 删除**，改引 `docs/engine-reservations.md`。
> - **仍然有效**：兵刃层 + 系别层的伤害构成、方式（内功/外功）× 性质（七系 + 无属性）2×8 正交、玩家抗性走条件修饰符而非属性。

一次攻击的伤害 = **兵刃层**（无属性、恒有、受外功防御减）+ **系别层**（附加伤害与效果，可有可无；= 兵刃层 × 系别系数）。伤害只有这两层，**没有第三类**。作用方式（内功/外功）与系别性质（七系 + 无属性）是**两个正交维度**（2×8 矩阵）。防御侧只有外功防御 / 内功防御两个属性；**玩家侧不设分系抗性**——玩家的抗性一律是**条件修饰符**。

## Context

`ADR-0006:7` 留下"元素标志"这个悬空字段（事件流带它却无人消费），而 `ADR-0008:3` 又出现 `damageType`（割/刺/瘀/内伤/照搬自 xkx100 的伤害类型）。两者语义不同且都未定案，需要一个 ADR 统一：伤害"是什么"（方式）、"什么性质"（系别）、"怎么算"（两层 + 管线）、"怎么防"（两防御 + 亲和度 + 效果抵抗）。同时要回答"抗性放哪"——属性还是修饰符——这直接决定角色 schema 与存档字段数。

> **术语纪律**：本 ADR 标题沿用 `BRIEF §12.4` 的条目名"元素（七系）"，仅作文档指代。**内容叙事文本禁用「元素」**，一律称「系别」（schema 字段 `element` 除外），见 `CONTEXT.md` 七系／系别词条的 Avoid。

## Decision

1. **伤害构成两层**：`兵刃层`（无属性、恒有、走外功防御）+ `系别层`（`兵刃层 × 系别系数`，系数是 config 里 7 个数）。**不存在第三类伤害**——拳脚（指虎/缠手）是正常外功门派形态，兵刃层照常计算，不是特例。
2. **两个正交维度**：作用方式 = 内功 / 外功（招式字段 `source`；**怪物攻击也标注**）→ 决定走哪个防御；系别性质 = 七系 + 无属性（8 个取值，字段 `element`）→ 决定附加效果。是 **2×8 矩阵**。内功 ≠ 心法（心法是被动武功，内功是作用方式）。
3. **防御侧两个属性**：外功防御 / 内功防御，百分比递减 `减伤 = 防御 / (防御 + K)`，K 在 config。旧名「护甲」已废弃。
4. **玩家侧不设分系抗性**：玩家抗性 = **条件修饰符**（`stat-modifier` + `condition: { source: { element: "fire" } }`），角色 schema 0 字段、存档 0 数据；抗性上限 `-75%`（走乘法区递减）。代价是 7 条词缀线的硬成本与 UI 的聚合读数。
5. **怪物亲和度**：`affinities: { fire: -50, water: +30 }`，是 **config 字段**（怪物与秘境条目）；只给 Boss 与特色怪设置，普通怪为 0，可按内容量线性铺开。秘境层 modifier（"此层火系伤害 +30%"）与亲和度**同族，复用同一套**。
6. **效果抵抗独立于减伤层**：减伤由防御负责，效果层由效果抵抗负责（「抗灼」→ 不被点燃 / 持续时间减半），走条件修饰符实现；**不称"免疫"**。
7. **主辅有序组合**：主（武功/门派）决定这一招"是什么"——提供该系核心效果；辅（装备）决定"额外怎么样"——对核心效果施加修饰。组合表**有序**（水火 ≠ 火水，同系 7 格除外）且**稀疏**（未定义组合走各系默认修饰）。
8. **相克不做"削弱"，做"变异"**：七根轴 = 破防／疫毒／滞缓／燃爆／守护／迅疾／霆爆，恰好 **2 真状态（木·中毒、火·灼烧）+ 5 纯数值**（MVP 形态）。
9. **伤害管线 12 阶段**（基础值 → 固定 → 百分比 → 乘法 → 暴击 → 攻方修正 → 守方减免 → 易伤/抗性 → 闪避 → 最终值 → 后续触发 → 应用），每个 modifier 声明作用阶段；第 12 步含**应用前拦截点**。注意：这与 `ADR-0005:6` 的"固定值 → 加法百分比 → 乘法区"（修饰符**聚合**规则）是两件事，本表是伤害**应用顺序**。
10. **引擎零题材词汇、零写死数量**：七系列表、系别系数、K 值、亲和度、组合表全在 `content/config/`；引擎只做键取值与集合求交（见 ADR-0011 第 6 条）。
11. **多目标与目标选择**：战斗形态**支持 1vN**（1v1 是特例）；`targetSelector` 支持 单体／全体／相邻／随机 N 个／除主目标外（BRIEF §11.2 引擎预留）。引擎只做**目标集合选择**与逐目标应用伤害管线，不按 selector 的具体值分支。

## Considered Options

- **设玩家侧分系抗性属性**（7 个抗性字段）：被否——角色 schema 与存档随系别数膨胀，且系别变化需改 schema；条件修饰符能表达同样的东西且可扩展。代价已认：7 条词缀线是硬成本、抗性需 -75% 上限、UI 需额外做聚合读数。
- **相克做"削弱"**（五行相克增减伤表）：被否——削弱只是数值打折，不产生玩法；改为"变异"（改造该系核心机制的参数，如木=扩散／火=引爆／水=延长）。
- **照搬 xkx100 的 `damageType` 伤害类型**（割/刺/瘀/内伤/抓伤）：被否——它是伤害模型语义而非文本语义，且与"方式 × 性质"正交模型重叠；战斗文本改由 motion 体系表达（见 ADR-0011）。
- **内力与内功防御硬挂钩**：被否——堆内力会成为唯一解；联动只走内容层词缀（见 ADR-0010）。

## Consequences

- 加系别 / 调系数 / 改 K 值 = 改 config，不动引擎；但组合表（有序、稀疏）需人工维护未定义组合的默认修饰。
- 玩家抗性是条件修饰符 → 存档无额外字段，代价是 UI 必须有"聚合读数"展示有效抗性。
- 减伤层与效果层分离 → 效果抵抗是独立维度，不能被"防御堆叠"绕过。
- `element`（系别）取代"元素标志"后，事件流字段成为 condition 修饰符的可匹配键（ADR-0006 据此修订），也是战斗文本 `{elementFlavor}` 的取值来源。
- 1vN 从第一天就是战斗形态，伤害管线对**每个目标独立跑一遍**；`targetSelector` 是内容可配参数，新增选择方式 = 加 config 取值，不改引擎分支。
