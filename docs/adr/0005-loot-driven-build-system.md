# 装备驱动的多流派构筑系统（暗黑/POE 式刷宝）

> ⚠️ **2026-09-01 更新**：第 2 条原写「境界提供基础数值与门槛」，境界已随 ADR-0019 取消，改为**武功等级 + 装备**提供基础数值、门槛走 `recommendedPower` 战力区间。其余各条不受影响。

用户明确要求《暗黑破坏神》《流放之路》式的装备驱动、多构筑玩法，取代初版"简单词缀"方案：

1. **掉落结构**：底材（每槽位多类，带固有词缀）× 稀有度（寻常 0 词缀 / 精良 1~2 / 罕见 3~4 / 绝世 5~6 含特色词缀）× 词缀阶位（T1~T3，高阶仅高层数秘境掉落）。掉落等级由秘境层数决定。（2026-08 修订：稀有度命名改为武侠语汇，见 ADR-0008）
2. **数值模型**：武功等级与装备提供基础数值，解锁门槛走 `recommendedPower` 战力区间（ADR-0019），强度主体来自装备词缀与心法的**修饰符聚合**。分层计算：固定值 → 加法百分比 → 乘法区。词缀、心法、增益丹统一产出修饰符，走同一条聚合管线（即 ADR-0004 的声明式效果系统）。
3. **流派来源**：词缀与武功通过**标签联动**（词缀"剑法冷却 -15%" × 武功标签"剑法"）。换一套装备即换流派；MVP 不做武器 socket，数据结构预留。
4. **装备循环**：掉落 → 穿戴 + 分解（得材料）+ 洗练（材料重随单条词缀数值）。词缀重铸、底材打造等完整工艺留后续。

## Consequences

- 修饰符聚合引擎是核心基础设施，先于战斗系统实现；所有数值来源（词缀/心法/buff）禁止直接改属性，必须走修饰符。
- **2026-08-30 澄清（实现边界）**："先于战斗系统实现"指**战斗代码从第一行起就必须走修饰符管线**，而非要求整条管线在战斗票之前全部完工。实现上拆为两步：秘境战斗票先落地**最小核**（固定值 + 加法百分比两层，够战斗计算用），装备票补齐**乘法区**与完整落地。判定标准是"战斗中不存在绕过修饰符直改属性的路径"，而非管线的完成度。
- 词缀池内容量按"条数 × 阶位"扩张（MVP 20+ 条 × 3 阶），Schema 需支持阶位表。
- 武功标签、词缀标签是内容层字段，标签枚举也在 `content/config/` 中定义。
