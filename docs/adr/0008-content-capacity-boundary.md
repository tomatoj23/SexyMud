# 内容承载边界：任务、NPC、知识技能明确不做

> ⚠️ **部分翻案（2026-09-01）**：**任务体系**与**NPC 独立集合**两条已由 **ADR-0016** 翻案——游戏形态改为文字 MUD，没有可交互实体与可承接的目标无法成立。翻案方式不是照搬 xkx100：任务按**进度翻译型**落地（不做对话树），NPC 立 `npcs/` 集合但**引用** `monster/` 数值而非复制（本文第 1 条「双处维护」的顾虑由引用规避）。
> **仍有效**：不做知识/生活技能；不做目录分层（归属字段化）；纯叙事道具用标签而非特殊类型；品阶/稀有度/显示档位三套语汇互不冲突。

对照侠客行（xkx100）内容资产做承载力分析后确定（原分析文档 `docs/design/` 下的早期分析已连同该目录于 2026-09-01 删除，结论见 `CONTEXT.md` 与本文）：我们的内容模型承载**武功体系、装备/物品、战斗文本、区域与怪物、门派与师承**五大块，**明确不做**任务体系、知识/生活技能、NPC 独立集合。同时确定扩大承载力的具体方式：武功条目加**前置**字段（伤害类型概念已删除——战斗文本由 motion 体系表达，见 ADR-0011），效果数值在内容生成期算成静态值（不由运行时插值）；生产活动加等级；内容条目用**门派/区域归属字段 + 校验器检查**表达分层，不做目录分层。

## Considered Options

- 照搬 xkx100 的任务四元组与 24 种任务阶梯：被否——放置游戏的任务形态（成就/悬赏/剧情）尚未确定，过早预留 schema 大概率返工。
- 立 `npc/` 集合并把怪物降为其一类：被否——师父天然属于门派数据，单独立集合会造成双处维护。
- 建 `knowledge/` 集合承载读书医术等 30 余种生活技能：被否——对放置主循环无贡献。
- 目录按"通用/门派专属/区域专属"分层：被否——字段化更利于编辑器表格视图、agent 批量操作与校验器，目录分层会让集合遍历与 id 唯一性复杂化。

## Consequences

- 这些"不做"是**当前边界**而非永久排除；将来要做任务时，先回到本 ADR 重新评估再决定 schema 形态。
- 被吸收的通用原则：纯叙事道具用**标签**表达（`tags:["quest"]` + 价值归零），不建特殊类型——标签化优先于类型化。
- 品阶/稀有度/显示档位是三套互不冲突的语汇（功法档次 / 器物档次 / 造诣深浅），命名见 `CONTEXT.md`，改动它们不影响掉落规则。
