# 融合式战斗呈现：对峙式视觉层 + MUD 式叙事层，强度随构筑变化

> ⚠️ **部分失效（2026-09-01）· 详见下文「配比定调」**
> - **第 1 条作废**：头像对峙布局、飘字、招式名大字弹出、大舞台 —— 全部取消。
> - **第 3 条的视觉强度映射作废**：飘字大小／配色／屏震／头像边框光环按境界分级 —— 全部取消。
> - 定案是**叙事 >> 视觉**：全屏小说式文本流为绝对主体（衬线、墨色），视觉层降级为顶部细状态条；强度差异改由**叙事档位**（片段数、后果词分档、会心标记）表达。
> - **仍然有效**：第 2 条（叙事层 = 战斗文本）、第 4 条（分层纪律：core 只吐结构化事件，不感知题材与文风）。

战斗画面采用双层呈现，且两层的表现强度都由构筑状态驱动（新手与宗师使出同一招，呈现必须不同）：

1. **视觉层**：头像对峙布局（立绘走资产约定路径，占位符兜底）+ 血条/状态栏 + 飘字 + 招式名弹出 + 可折叠日志。
2. **叙事层**：战斗日志为 MUD 式武侠招式描写。文本模板与词库是内容文件（`content/combat-text/`），带 13 个槽位变量（`{attacker}` 语法，详见 ADR-0011）；模板按品阶定片段数（3-7 段），后果词库按 **5 维分池**（伤害档 × 剩余生命档 × 作用方式 × motion × 系别），命中类型（暴击/闪避/反伤）与节奏档决定抽取域。频率控制：普通命中短句，关键节点才触发完整描写。
3. **构筑驱动的强度映射**：`core` 事件流携带完整语境（伤害、暴击、系别 + 作用方式（内功/外功）、伤害占比四档、品阶、造诣档位），呈现层据此映射叙事档位（视觉强度映射已按上文配比定调作废）。配色表、档位阈值均为内容配置。
4. **分层纪律**：`core` 只吐结构化事件，不感知题材与文风；文本模板引擎与视觉映射是 UI 层组件，完全由内容驱动。

> **配比定调（2026-08-31 用户拍板；原型 `prototype/battle-ui/` 的结论已迁移至此，原型随之删除）**：两层不是对半，**叙事 >> 视觉**。
> - **叙事层是绝对主体**：全屏小说式文本流（衬线、墨色），伤害数字**行内嵌入**文本而非独立元素；会心一击用金框强调。
> - **视觉层降级为辅助**：仅顶部细状态条（双方头像 + 气血／内力微条）。**不做**大舞台、大头像、飘字飞行、招式名大字弹出。
> - **掉落不打断叙事流**：行内交代（「遗落 玄铁重剑（罕见）」）+ 探索结束的结算段；**不用**浮动 toast。
> - 因此上文第 1 条的「飘字 + 招式名弹出 + 头像对峙布局」**已作废**；第 3 条的视觉强度映射（飘字大小／屏震／头像边框光环）**一并作废**——强度差异改由**叙事档位**表达（片段数、后果词分档、会心标记）。

## Consequences

- 事件结构必须从第一天就携带呈现所需语境（标志位、占比），后补会伤及存档与模拟器兼容性。
- 模板引擎是 UI 层基础设施，先于战斗页开发；`content/combat-text/` 是 agent 批量生产的主要场景之一。
