# 兽（驭兽）：本质是装备，不是战斗单位；七系各一只机制放大器

兽 = **一组修饰符 + 一段可声明的叙事片段**。引擎不需要认识"兽"，只知道"带 narrative 的装备"。兽**不造成该系伤害，而是改造该系机制的行为方式**（机制放大器，不是伤害复制品）。边界：不能成为敌人攻击目标、不能有血量会死、不能在主人不出招时独立行动。

## Context

> ⚠️ **理由已更新（2026-09-01）**：原文的「离线 O(1) 结算 / 无人值守挂机」是放置期理由，ADR-0016 已定离线不自动战斗。MUD 下结论不变、理由更强：**战斗是命令驱动的，任何需要玩家额外操作的单位都会加重操作负担**；且兽本质是装备（修饰符 + 叙事片段），这个定位在 MUD 里同样成立。

玩家希望有"伙伴"感的内容，但战斗不应增加操作负担：任何"会死、需要被保护、会独立行动"的单位都会让玩家多一层指令要下。同时七系需要额外的构筑维度（ADR-0009 已定主辅组合，兽提供第三条线）。MVP 只要 2 只，但要保证将来补到 7 只是纯内容追加。

## Decision

1. **本质是装备**：兽 = 修饰符集合 + 可声明叙事片段，落在装备体系内（独立"随从"栏，**不占 7 个装备槽**）。引擎不为兽引入单位概念。**数据归属：独立 `content/beast/` 集合**（第 13 个内容集合，schema `beast.schema.json`，id 前缀 `bst-`、一系一只语义命名；slot 由 schema const 锁死为 `beast`）。
2. **三条边界（不可越）**：① 不能成为敌人攻击目标；② 不能有血量、不会死；③ 不能在主人不出招时独立行动。石龟"替你挡下"实为**减伤修饰符 + 叙事包装**，不是一次真实的承伤事件。
3. **机制放大器模型**：兽改造该系核心机制的**某个参数**，而不是复制该系伤害——木 = 扩散（毒蜂：`targetSelector` 单体 → 多个）／火 = 引爆（火鸦：trigger + `condition`）／水 = 延长（寒蟾：`duration`）／金 = 维持（铁啄鹰：`duration` 不衰减）／土 = 转移（石龟：`stat-modifier` 减伤 + 叙事包装）／风 = 缩短（灵隼：`rate-modifier`）／雷 = 追加（雷兽：`condition: on-crit` + `instant-damage`）。
4. **形态**：驭兽（真实动物被驯养驱使）。机关傀儡留待门派设计时评估；**召唤物排除**（凭空生成属仙侠谱系，且与文风约束冲突）。
5. **获取与成长**：门派贡献兑换 + **随造诣自动成长**（避免第二个养成循环）；喂养 / 进化留 v2；任务奖励途径排除（ADR-0008 明确不做任务体系）。
6. **MVP = 2 只**：木系毒蜂（进攻型）+ 土系石龟（防御型）。其余五系待模型验证后补——届时加兽是**纯内容**。
7. **引擎预留（必须现在留）**：
   - 致命判定需要"应用伤害之前"的**拦截点**（形状清单 #8）；
   - primitive 支持 `chance` 参数（概率触发，属参数非坑）；
   - 效果实例带 **CD 状态，运行时数据进存档**（形状清单 #9，真坑）；
   - "参与者集合"抽象（形状清单 #5）**仍要做**——兽现在用不上，但秘境定时波次已经用上。

## Considered Options

- **兽作为独立战斗单位**（有血量、可被攻击、可独立行动、会死）：被否——需要仇恨/AI/死亡处理，成本远超收益，且会给命令驱动的战斗再加一层操作负担。
- **兽复制该系伤害**（作为第二个伤害来源）：被否——等于再开一条伤害管线，与七系主辅有序组合（ADR-0009）重复；改为改造已有机制的参数，零新管线。
- **兽走任务奖励获取**：被否——ADR-0008 已明确不做任务体系。
- **独立的 `beast/` 集合**：✅ **采纳**——引擎经 ContentRegistry 加载内容，条目放哪个目录对引擎透明（"数据形态镜像引擎视角"不成立：引擎需要的统一性由 schema 字段形态保证，不由目录保证）；集合划分的真依据是**内容生产规则**——装备 = 底材 × 稀有度 × 词缀（掉落管线输入，42 底材约 294 项的密集结构），兽 = 一系一只（element 身份、无稀有度、无词缀、不走掉落、走 exchange 兑换的稀疏结构），生产节奏完全不同；独立集合还带来掉落引用天然隔离（掉落配置在结构上引不到兽条目）、`equipment/` 语义保持"底材与词缀池"名副其实、编辑器表单按集合生成无需 oneOf 分叉。代价：12→13 集合、16→17 schema（草案阶段近零）。
- **并入 `content/equipment/`（kind: beast，oneOf 第三支）**：被否——曾在 c2725cd 落地、复盘推翻。其三支柱论据逐一失效：① "镜像引擎视角"——注册表对目录透明，装备体系（运行时概念）≠ equipment 目录（内容组织）；② "获取流不同不构成分集合理由"——对，但**生产规则**不同构成；③ "12 集合 / 16 schema 计数零变动"——弱论据，草案阶段加一集合近零成本。

## Consequences

- 加兽 = 纯内容追加（七系各一只，只差内容与数值），不动引擎。
- **CD 状态进存档**是硬要求：版本化存档迁移必须容纳"效果实例的 CD 运行时数据"。
- 兽的成长挂造诣与门派贡献，**不引入第二个养成循环**（否则玩家的指令与注意力会被摊薄）。
- 石龟这类"承伤"表现全部走修饰符 + 叙事包装，UI 与文本不区分"真实承伤"。
- 内容集合 12→13、schema 16→17（`content.md` 目录与 `schemas/` 各加 `beast`）；掉落管线（ADR-0012）永不触及 `beast/`——引用隔离是结构保证，无需校验规则兜底。
