# 两层推进：世界层随命令推进，实体层按需推进

ADR-0032 把在线心跳与离线结算收敛成同一个推进函数。`spec/04` §4.1 原本没有说清楚**推进的是谁**：如果每条命令都把所有实体一起推进，那么每个实体的「上次结算 tick」会被刷成「现在」，**离线补算的跨度恒为 0，离线结算等于没做**。本文定这件事，以及结算事件的时间戳。

## Context

- ADR-0016 §4：离线结算 =「进入游戏时一次性 O(1) 补算」。它要成立，就必须有一个「上次结算到哪」的数。
- ADR-0022 §5 / ADR-0025 §四：**时间推进按需求值**，而不是每 tick 遍历。这是对 Evennia「Script 实体 + 每对象定时器」的直接回应。
- ADR-0028 §1：静态在场 / 动态占用二分，NPC 不入档。今天运行时实体只有玩家，但这个数量会随后续里程碑增长（物化物品、有状态 NPC 都会进同一棵树，ADR-0028 §1）。
- ADR-0024 §2 确定性清单要求重放一致。

## Decision

### 1. 世界层：每条**进入执行段的**命令处理前补到高水位

到期桶、一次性世界事件这类**挂在世界上的东西**，在每条进入执行段的命令（`ok`／`rejected`）处理前一次性补到高水位。`invalid` 不推进（见 ADR-0032 §4：否则刷乱码即可快进世界）。

由此**全局只需要存 `nowTick`**（推进后它就是「世界已结算到哪」），不需要一个单独的 `lastSettledTick` —— 那会是与 ADR-0031 §4「不保留两个真相」同类的漂移源。

### 2. 实体层：只推进这条命令的 actor

补偿结算与离线补算**只针对这条命令的 actor** 发生，用他自己的 `lastSeenTick` 算跨度。

⚠️ **不是「所有在场者」**：在场 ≠ 在线。离线玩家的实体仍在树里、仍在同房间；若把在场者一起推进，**甲的活动会消耗乙的离线补算额度**，乙的离线结算就不再发生在「他自己回来」的那一次。actor-only 是唯一无歧义的解释。将来若需要「被动参与者（如被攻击者）也推进」，那是独立决策。

这正是 ADR-0022 §5「按需求值」的字面实现：**不在线的实体没有被「需求」，就不推进。**

场景核对：甲 tick 0 下线、乙 tick 100 下线，都在 1000 回来 ——
- 甲先回：世界层 0→1000 跑完到期桶；实体层结算甲 0→1000（这次就是「离线结算」）。
- 乙后回：世界层已到 1000，不再跑；只结算乙 100→1000。

`lastSeenTick` **由引擎在结算完该实体后写入**，宿主不碰 —— 否则「上次在线」会被宿主的时钟实现污染，而这正是 ADR-0031 把 `Clock` 翻转出去要防的事。

### 3. 结算事件的时间戳必须写 `dueTick`

tick 300 本该炸的东西在 tick 1000 才被补跑，它的事件里写 **300**（它本该发生的时刻），不是 1000（它被补跑的时刻）。

写 1000 的话，事件顺序会依赖**谁先上线**，重放就不再确定 —— 正是 ADR-0024 §2 要封死的。

### 4. 结算事件与触发它的命令同 seq，且排在命令自身事件之前

世界先推进到「现在」，命令随后才发生。玩家三天后回来，先读到「这三天发生了什么」，再读到「你向北走」。

`GameEvent` 必须带 `seq`（ADR-0025 §1.1），而结算事件不是任何输入直接产生的 —— 借用触发它的那条命令的 seq，保持「seq = 第 N 条命令产生的全部事件」这个语义不被稀释。

### 5. 宿主心跳显式给 seq

宿主在没有命令时也可以调推进（纯心跳）。它没有 actor，而 `Command.actorId` 是必填 —— 所以**不伪造一条系统命令**，而是让调用方显式给一个 seq，与命令 seq 处在**同一个单调递增空间**。

## Considered Options

| 方案 | 否掉的理由 |
|---|---|
| **只有世界层**（`lastSeenTick` 恒等于 `nowTick`） | 离线结算跨度为 0，等于没做 |
| **只有实体层**（世界事件绑在第一个回来的实体身上） | 甲回来才炸、乙回来不炸 —— 世界状态依赖谁先上线 |
| **把世界挂在每个实体上各自推进** | 同一个炸弹被 N 个实体各触发一次 |
| **心跳包成一条 `actorId: ""` 的系统命令** | 为了心跳伪造一个 actor，稀释了「命令」这个词；且把 `actorId` 必填这条的规则打出一个洞 |
| **心跳不产生对外事件** | UI 拿不到天气变化，只能轮询；而轮询正是 ADR-0022 §5 要消灭的东西 |

## Consequences

- `EntityState` 多一个可变槽 `lastSeenTick`（今天是只读 id + 可变 locationId/flags/tags）。
- 「进入游戏」这个动作在票里的形态是：**一条 tick 很大的命令**（由宿主维护自己的 seq）。
- ⚠️ 如实记录（不是待办）：今天运行时实体只有玩家，所以第 2 条的「多玩家互不污染」只能在合成测试中行使，在真实内容里暂不可观测 —— 性质同 `spec/00` 记 M3-T6 的那两条限制。
