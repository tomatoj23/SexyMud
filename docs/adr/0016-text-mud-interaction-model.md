# 文字 MUD 交互模型：命令层内容化 + 世界模型 + 双时钟（MUD 为主，放置为辅）

游戏形态由「放置 RPG」改为「文字 MUD」。核心不是换皮，是**换交互模型与时钟语义**：玩家用命令驱动角色在世界里行动，放置机制降级为补充。

> ⚠️ **与既有定案的冲突（显式标注）**：本文第 3 条 _Contradicts ADR-0008（「不做任务体系、不做 NPC 独立集合」），but worth reopening because_ MUD 没有可交互实体与可承接的目标就无法成立，且 ADR-0008 自述"这些不做是当前边界而非永久排除，将来要做时先回到本 ADR 重新评估"。本文第 5 条修订 `CONTEXT.md` 的 intent 词条。

## Context

现有引擎的交互面只有三个动作（`startActivity` / `stopActivity` / `sync`），时钟只有一个语义：墙钟驱动的离线补算（`createGame.ts` 的 `sync()`）。这套模型服务放置循环，但撑不起 MUD——玩家不能输入、世界没有空间、战斗回合被墙钟绑架。

## Decision

1. **玩法主次定案：MUD 为主，放置为辅**。在线命令交互是核心体验；离线只结算**不产生叙事**的时间推进——气血／内力恢复与基础武功熟练度（带上限，上限是刻意制造回归动机）。**离线不自动战斗、不自动推层、不产掉落。** 理由：放置的「我不玩也在赢」与 MUD 的「我在操控」直接冲突；若离线能赢，最优解变成不上线，MUD 即死。
2. **命令层内容化**：新增集合 `commands/`。每条命令 = `{ id, verbs[], aliases[], 参数形态, 目标解析规则, 前置条件(条件修饰符), 效果(引用 effects), 拒绝文案 }`。引擎只做通用管线：**分词 → 动词查表 → 参数解析 → 前置校验 → 执行 effects → 吐事件**，自己不认识任何动词。"打/杀/attack/kill" 全部是内容里的 `verbs` 数组，不是引擎的 `switch`。加命令 = 加内容文件，引擎零改动。
3. **世界模型**：新增集合 `rooms/`（具体空间：出口、进入文本、常驻实体引用、所属区域）与 `npcs/`（可交互实体：外观称呼、对话、行为、可否触发战斗）。
   - 与 `dungeon/` 的分工：`dungeon/` 保留**规则层**（分层、驻守、产出），`rooms/` 承载**空间层**（房间与出口），两者用**归属字段 `zoneId`** 关联（沿用 ADR-0008「归属字段化、不做目录分层」）。
   - 与 `monster/` 的分工：`monster/` 保留**战斗数值 + 叙事形象**；`npcs/` **引用** `monsterId`，不复制数值。这是 ADR-0008 否掉「立 npc 集合并把怪物降为其一类」的原因（双处维护）——本方案用引用规避了它。
   - 任务：按 `docs/quests/` 的**进度翻译型**落地（完成条件只映射现有系统的可观测量，零新交互、零新数值），**不做对话树**。
4. **双时钟**：把 `sync()` 拆成两个语义，不共用代码路径。
   - `tick()`——**在线世界心跳**：由 host 驱动，**固定步长**（`content/config/`：`tickSeconds`），推进战斗回合 / 持续伤害 / 状态倒计时 / NPC 行为。命令在心跳边界之间插入。固定步长而非墙钟，是为了让战斗结果不受渲染与网络抖动影响。
   - `settleOffline()`——**离线结算**：进入游戏时一次性 O(1)，只按第 1 条白名单结算，上限由 config 定义。
   - 两者共用同一族「离线上限」配置项，但**语义隔离**：心跳不知道离线的存在，离线不推进战斗。
5. **intent 改判（修订 `CONTEXT.md`）**：由「MVP 唯一来源 = 加权轮盘（auto-source）」改为 **manual-source 优先**——命令输入是主要 intent 来源；auto（加权轮盘）降级为「未下指令时的默认行为」与「自动应战模式」。这正好吃掉原定案预留的 `manual-source` 注册位，core 零改动。

## Considered Options

- **命令硬编码在 TS（`switch (verb)`）**：被否——加命令要改引擎，无法被 `content:check` 校验、无法被编辑器编辑，直接违反硬标准 1（引擎零题材词汇）。
- **照搬 xkx100 的 LPC 命令体系**（`cmds/` 一文件一命令，命令文件里写业务）：被否——命令即逻辑，内容与代码不分家，同样违反硬标准 1。可借鉴的只是其**动词覆盖清单**（`docs/research/xkx100-*.md`）。
- **不拆时钟，沿用单个 `sync()`**：被否——会出现「我不在线时房间里的怪也在打我」；且战斗回合被墙钟绑架，帧率/延迟直接改变战斗结果，与第 4 条的确定性目标（ADR-0017）冲突。
- **保留 auto-source 为唯一来源**（即「放置内核 + 文字皮肤」）：被否——用户已定案 MUD 为主；该方案下玩家无操控感，MUD 不成立。
- **任务直接做成对话树**：被否——放置节奏下玩家不会读对话树；`docs/quests/` 已论证「任务 = 进度翻译」才是本作的任务形态。

## Consequences

- **资产零浪费**：ADR-0011 的战斗文本系统（13 槽位 / 片段序列 / 5 维后果分池）本就是一套 MUD 文本引擎，直接成为叙事主干；`docs/research/xkx100-*.md` 的房间/出口/肢体槽位/伤害分档调研直接指导 `rooms/` schema 与命令动词清单；`docs/martial/`、`docs/quests/` 的设计稿从「放置的附属」升级为「MUD 的主菜」。
- **新增成本**：3 个集合（`commands/` `rooms/` `npcs/`）+ 3 个 schema，必须走「schema 三处同步」（core 类型 / 编辑器 / `docs/agents/content.md`）与 `content:check` 硬门禁。
- **命令解析的边界**：引擎做形态解析（分词、量词、目标指代如「第一个」「它」），**不做语义解析**——「把木剑给店小二」里「木剑」是物品还是 NPC，由命令条目的**目标解析规则**（内容）决定。
- **战斗回合的呈现粒度**：心跳是固定的，但叙事输出可以按事件累积后批量吐出（避免刷屏），节流阈值是 config 项而非引擎常量。
