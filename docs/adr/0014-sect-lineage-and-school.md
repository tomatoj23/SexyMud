# 门派：武功池 + 缺省系别 + 生产加成三件套；脉是武功池的标签，不是身份选择

> ⚠️ **2026-09-01 更新**：文中 `BRIEF §11.1` 指向的 `docs/design-spec-BRIEF.md` **已于 2026-09-01 删除**，改引 `docs/engine-reservations.md`。其余（门派三件套、脉是标签而非身份、已学武功与门派解耦）**仍然有效**。

门派 = **武功池 + 缺省系别 + 生产加成**（外加贡献货币、脉、师父）。**脉（`lineageId`）是武功池的细分归类标签，不是玩家的身份选择**——可以同时拥有多个，玩家通过**装配**（招式 4 / 心法 3 的槽位限制）来"选"。五条引擎预留必须在 MVP 前留下，其中"已学武功与当前门派解耦"最关键。

## Context

门派是"出身组织"（CONTEXT.md 门派词条），决定可学武功池与生产加成；流派则是玩家用装备 + 武功装配玩出来的构筑，**不绑定门派**（跨门派混搭可产生新流派）。这两件事必须分开：一旦把"已学武功"挂在门派名下，将来做换派/偷师/叛派就会退化成"剥夺玩家资产"的问题，而不是"获取权限"的问题。

## Decision

1. **三件套**：武功池（`martialPool`）+ 缺省系别（`defaultElements`）+ 生产加成（`productionBonus`），外加门派贡献货币、脉、师父（`sect.masters`）。
2. **脉（采用）vs 专精（避免）**：
   | | 脉（采用） | 专精（避免） |
   |---|---|---|
   | 是什么 | 武功池的**归类标签** | 玩家的**身份选择** |
   | 能否同时拥有多个 | **能**（受贡献/前置限制） | 不能（互斥） |
   | 谁来"选" | 玩家通过**装配**选（招式 4 / 心法 3 槽位限制） | 系统让玩家进入时选死 |

   实现：与 `sectId` 并行的 `lineageId` 字段，校验器照 `sectId` 那套做覆盖与连通检查。
3. **门派节奏差异**（内容层，引擎不读）：丐帮 = 火 / 雷，**爆发型**（短时间倾泻，之后疲软）；武当 = 水 / 土，**持久型**（防守反击，拖得住）；唐门 = 木 / 金，**累积型**（毒/破防叠加，越打越疼）。
4. **五条必须现在留的引擎预留**：
   1. 门派内进阶是**运行时进度，进存档**；
   2. **已学武功必须与当前门派解耦（最关键）**——已学武功是玩家的属性，门派只是获取来源（如同从某校毕业不会因跳槽而失去学位）；
   3. `condition` 匹配维度可扩展（见 BRIEF §11.1）；
   4. 门派间关系是**一张内容表**（正派/魔教、同盟/敌对将来会变），引擎只查表；
   5. 门派归属是**运行时状态、可变更**（存档存"当前门派"字段）。
   > 其余 14 项机制（生产加成、门派贡献、门派专属装备/词缀/兽/秘境、被动加成、竞技排行等）**无需预留**——归属标签、已有 modifier 或内容配置即可。
5. **入门条件与师父**：入门条件 MVP **恒真**，但"学习武功"流程**带条件检查点**（即使条件恒真）；师父（`sect.masters`）**先只留字段**，无实际内容。

## Considered Options

- **脉做成"专精"**（玩家进入门派时选死、互斥）：被否——把构筑空间锁死在系统层，与"流派由玩家玩出来、不预设标签"（CONTEXT.md 流派词条）直接冲突。
- **已学武功挂在门派名下**：被否——换派 / 偷师 / 叛派惩罚会变成"剥夺资产"的问题；正确做法是解耦，让惩罚退化为获取权限问题。
- **门派间关系硬编码**：被否——正邪、同盟敌对将来会变，必须是内容表（引擎只查表）。
- **师父建独立 NPC 集合**：被否（ADR-0008）——师父归入门派条目的字段，不设独立 NPC 集合。

## Consequences

- 换派 / 偷师 / 叛派将来**全部退化为"获取权限"问题**，不需要动资产模型（MVP 不可换派是内容规则，不是数据结构限制）。
- 脉只增加内容条目与校验（覆盖 + 连通），引擎零改动。
- 门派内进阶与当前门派是运行时状态 → **进存档**，版本化存档迁移需容纳这两个字段。
- 门派节奏差异（爆发/持久/累积）是文案与内容调参，引擎不感知"节奏"概念。
