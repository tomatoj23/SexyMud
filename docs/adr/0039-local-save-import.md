# 本地存档导入：D7 保命通道的对偶——验证先行、确认明示代价、存未迁移原文

D7 的保命通道是「导出 JSON」（ADR-0002 §21），但**导出有、导入无**：导出的档救不回来，保命通道是单向的；本地槽的写入方只有下载（裁决的「以云端为准」）——「文件 → 槽」这条最朴素的恢复路不存在。本票（#33）立导入：`CloudSavePanel` 上「导出／导入」成对，文件选择、机器验证、二次确认、写槽。六条定案先落工作稿 `.scratch/grill-2026-09-29/local-import/DECISIONS-WIP.md`（grilling 两轮六问＋2026-09-29 复查修订），跑绿后升级为本 ADR 与 spec/04 §1.8。立否三条件自评：**难逆**（导入语义与失败词表进封闭联合，回改波及机器＋面板＋文案）／**会困惑**（「验证用 restoreWorld 却存原文」「确认为什么拆在链中间」无记录必读不懂）／**真权衡**（九条被否路线）——三条齐，立。

## Context

- 导入＝**覆盖本地槽**的破坏性动作，与上传/下载同属 D7 的「明示代价」族；但它的载荷来源是**玩家手里的文件**——#31 收掉「视图作载荷」后留下的另一半问题（「上传到云端」无源可传的「源」）自此有了答案。
- 版本兼容口径已由 ADR-0036 D3 定死（云端不迁移、迁移只有一条链）；导入同律：**原样进槽**，校验归校验、存储归存储。
- `restoreWorld` 是已导出纯函数（migrate 链＋九类载荷校验），可当「restore 必可载」的验证器——core 零改动红线不动。
- ⚠️ 2026-09-29 复查（`REVIEW-2026-09-29.md` H3）修正了原 D4 机制：「跑 `migrateSnapshot` 链验证」不成立——九类载荷校验在 `readSaveData`、由 `restoreWorld` 才跑，信封好载荷坏的档会被假成功收下。

## Decision

1. **D1 入口与导出对偶同居**：`CloudSavePanel` 上「导出／导入」成对（文件选择器选 `.json`）。导出今天就住这里，D7 保命通道拆两处难找；「本地动作住云面板」的耦合是宿主整理（W6）的议题，不由本票顺手定。
2. **D2 写路径收进机器**：`CloudSync` 收导入操作（parse → 验证 → `LocalSaveStore.save` → 失败分类 → `views.local` 随写刷新），面板只做文件选择＋确认。「视图随读写刷新」（#31 D3）与「失败盖过旧裁决」（D8）两律都在机器——面板直写必让 `views.local` stale。实现形态为两段 `beginImport`（读＋parse＋验证＋暂存）/`commitImport`（无参写槽）：**二次确认必须坐在验证之后、写入之前**，单操作容纳不下（AC「损坏/版本不可载不进确认」），拆段是被 AC 倒逼的最小形态；`commitImport` 无参是 #31 律的镜像（暂存载荷即写入载荷，视图永远不是载荷源）。
3. **D3 解析先行＋确认无条件化＋冲突态禁用**：验证通过才弹二次确认（不给确认一个无效导入——先确认后解析会让玩家对无效文件承诺代价），明示代价「**覆盖当前本地存档、不可撤销、建议先导出保命**」；任何视图缓存不得跳过破坏性二次确认（#31 复查轮教训）；**冲突态禁用导入**（裁决中不可动赌注，D7 同律）——机器守卫为准，面板 disabled 是视图门/展示（「双保险」措辞已废：保险只有机器一层）。
4. **D4 版本校验调 `restoreWorld`**：用已导出纯函数验证「restore 必可载」（migrate 链＋九类载荷一并验），**存未迁移的解析结果**（「原文」＝不带迁移改写）。被告诉「已导入」就必须真能载入。失败按因分词：**分词探针喂空载荷问链能否走**——`migrateSnapshot({ version, data: {} })` 只在版本戳本身走不了（非法/过新/缺步）时抛 ⇒ `file-version`；探针走得动 ⇒ 伤害在载荷 ⇒ `file-corrupt`。⚠️ 复查收口（2026-10-01）：探针**绝不能喂真载荷**——敌意形状（`data: null`）会**崩掉** v1 迁移步（步内 `data.nowTick` 访问），实测同一种伤害曾被喂真载荷的探针按版本戳漂移成两词（v1 `file-version`／v2 `file-corrupt`）；词名的是伤害，不是版本戳的意外。
5. **D5 失败口径走机器 `run` 同口径**：`file`（文件读不出）｜`file-corrupt`（解析损坏或载荷类验证失败，不半写）｜`file-version`（版本/迁移类验证失败）｜写入失败沿 `local`（配额）/`local-unavailable`（#32 D4 词）；成功 outcome **`imported`**（与 `saved`/`downloaded` 同律，D8 失败盖过旧裁决）；用户取消文件选择＝静默，不算失败。失败源是文件本身 ⇒ `file-*` 与 `local-*` 对仗（`local-corrupt`＝槽坏、`file-corrupt`＝文件坏）；文件读取在**动作最前端**（#31 D2 同律），故读失败也是机器裁决、机器收文件的最小切片 `ImportSource`。
6. **D6 红线**：core 零改动；不做槽管理、不做自动上传/合并（版本兼容交 `migrateSnapshot` 一条链，导入原样进槽；活世界写入方是命令层的活）。

## Considered Options

- **入口独立「本地存档」面板**：被否——保命通道拆两处难找；面板耦合是 W6 的活。
- **面板直拿 `LocalSaveStore` 写**（开新 props）：被否——`views.local` 必 stale（#31 教训）；破坏性动作纪律分裂到面板。
- **先确认后解析**：被否——玩家对一个无效文件承诺「覆盖」代价。
- **版本只做「过新」轻校验／不校验交 restore 时才炸**：被否——挡不住 migrate 链中途炸的档与载荷坏的档，「已导入」假成功，玩家在最坏的时机（载档）才发现。
- **只跑 `migrateSnapshot` 链验证**（原 D4 机制，复查否决）：被否——九类载荷校验在 `readSaveData`/`restoreWorld`，信封好载荷坏的文件照样假成功。
- **成功提示面板自持**（不进 outcome）：被否——D8「失败盖过旧裁决」纪律在机器，面板自持会漂。
- **失败词 `import-*` 前缀**：被否——失败源是文件不是「导入」动作；`file-*` 与 `local-*` 对仗。
- **单操作 `importLocal(text: string)`**（接口钉子原型）：被否——确认无处安放：验证在确认前、写在确认后，一条链塞不下三段；且 `file`（读不出）必须是机器裁决，`text` 入参把文件读取留在面板，读失败就再也进不了词表。两段＋`ImportSource` 是被 AC 倒逼的最小形态（钉子自注「命名可微调」，此处连形态一并修，留痕于此）。
- **分词探针喂真载荷**（首版实现）：被否（2026-10-01 复查实证）——迁移步会被敌意形状**崩掉**（`data: null` 在 v1 步的 `data.nowTick` 上抛 TypeError），同伤两词随版本戳漂移；探针换空载荷后，「探针抛出＝纯版本/缺步类」才成立。

## Consequences

- 保命通道闭环：导出的档救得回来；损坏槽的三条出路（修／导出 salvage／**导入覆盖**）齐了（§1.7 D8 指路句补 §1.8 链接）。
- 破坏性确认与上传/下载同律（D7 族），但确认行从此有第三个成员；「确认无跳过」「按钮视图门」断言随 W6 面板测试基建落地（apps/web 今天零 React 测试基建，本票机器面不背该测试名）。
- **暂存语义的最小定死**（复查收口后双向对称）：守卫拒绝（busy/过期/冲突）**不动**暂存；**真尝试一律消耗**——pick 尝试（`beginImport`，成败皆耗：失败的重选不能让旧文件落在下一次确认之下）与提交尝试（`commitImport`，成败皆耗：确认已答、写未试也算答，重导即重试）。机器实例随重登重建，滞留暂存随之消亡。
- 测试网 806 → 822 用例（core 30/633、web 11/189，`cloud-sync` 45 → 61；复查轮补分类回归、暂存生命周期与无参签名机械钉——签名放宽即 `TS2578` 编译不过）。
