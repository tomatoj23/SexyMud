## 2. 武功分类体系（问题 1）

### 2.1 两级元分类

每个武功文件声明两个属性（来源：`kungfu/skill/anran-zhang.c` 等所有武功文件头部）：

- **`type()`**：`martial`（武功）或 `knowledge`（知识技能）。
  - `knowledge` 类举例：读书识字 literate、佛法 buddhism、医术 medicine、烹饪 cookery、阵法 array、赌技 gambling 等（`doc/help/skill` L32-44 的"技能列表"）。
  - 知识技能不受经验限制，只受天赋/门派/冲突技能限制（`doc/help/skill` L22-25）。
- **`martialtype()`**（武功内部三分类）：`skill`（外功招式）、`force`（内功）、`dodge`（轻功）。
  - 来源：抽样 all 各文件，如 `kungfu/skill/cuff.c`（skill）、`kungfu/skill/jiuyang-shengong.c`（force）、`kungfu/skill/lingboweibu.c`（dodge）。

### 2.3 门派归属维度

总表每行格式为"中文名 门派 拼音id"，如"太极剑法 武当 taiji-jian"（`doc/help/skill` L103）。门派 30+ 个（少林、武当、丐帮、古墓、逍遥……），同一武功可属"公共"（如降龙十八掌、九阴真经系）。部分武功在南北少林有两个近乎复制品（如 damo-jian / damo-sword）。

### 2.4 特殊归类

- **降龙十八掌**是"组合武功"：主文件 `kungfu/skill/xianglong-zhang.c` 含 `sub_skills` 映射，18 招各自是独立武功文件（kanglong-youhui、feilong-zaitian……各 150 级），练满全部可"演练"合成主武功（L51-99）。
- **内功互斥**：`kungfu/skill/force.h` 的 `valid_public()` —— 修一门新内功前必须散掉其他所有内功（"你不散掉XX，如何能修习YY"），例外靠白名单（shenzhao-jing、taixuan-gong）。

## 3. 武功文件结构（问题 2）

以 `kungfu/skill/anran-zhang.c`（黯然销魂掌）为标准模板，字段语义如下：

| 字段/函数 | 语义 |
|---|---|
| `action` 数组 | 招式表：每项 `{action(战斗文本), skill_name(招式名), lvl(解锁等级)}` |
| `valid_enable(usage)` | 本武功可激发为哪些用途，如 `usage=="unarmed" \|\| usage=="parry"`（L90） |
| `valid_learn(me)` | 学习前置条件，不满足返回一句提示文本：师承限制（"你只能向杨过学"）、先修武功等级（"玉女心法不熟练"）、内力上限（"max_neili < 1500"）、姿势限制（"必须空手"）（L92-108） |
| `practice_skill(me)` | 练习（自行苦练）的消耗：扣体力 qi、扣内力 neili，各 30-50 点；有姿势/兵器限制（L110-121） |
| `query_skill_name(level)` | 按当前等级返回应显示的招式名（向下取最大解锁档）（L122-128） |
| `query_action(me, weapon)` | 战斗时随机选一个已解锁招式，并输出数值效果包（L129-155） |
| `learn_bonus / practice_bonus / success` | 学习/练习效率系数（基本武功 30，名门武功 0-10） |
| `power_point(me)` | 威力系数，通常 1.0，门派专属轻功对本门弟子 1.5（`lingboweibu.c` L50-53）；引擎强制钳制在 1.0~1.5（`adm/daemons/combatd.c` L216-225） |
| `perform_action_file` | 指向同名子目录的绝招（perform）文件 |
| `help` | 武功介绍文本（武侠典故）+ 学习要求清单 |

### 3.1 招式数值效果包（query_action 返回值）

`anran-zhang.c` L131-154 注释明确定义了四个效果维度：

```
d_e = dodge_effect（影响对手躲避）
p_e = parry_effect（影响对手招架）
f_e = force_effect（内劲加成）
m_e = damage_effect（伤害加成）
```

每项给出一个**区间 [下限, 上限]**，按招式序号线性插值——即**越靠后（越高级）的招式效果越强**。例如黯然销魂掌：dodge 10→30、parry -45→25（负值表示更难被招架）、force 300→400。打狗棒法额外有 damage 100→300（`dagou-bang.c` L66-73）。

同时输出 `damage_type`（伤害类型），如 `random(2) ? "内伤" : "瘀伤"`（anran-zhang）或固定"挫伤"（dagou-bang L90）。

### 3.2 三类武功的差异

- **内功文件**（inherit FORCE）：无招式表，改挂 `exert_function_file`（运功功用，指向 `kungfu/skill/<内功>/` 子目录：heal 疗伤、roar 狮吼、powerup 提升战力等，见 `doc/help/neigong`）；可定义 `hit_ob`/`be_hit_ob`（命中/被命中时的附加效果与文本，由战斗引擎回调，`combatd.c` L483-497）。学习条件走 `force.h` 的内功互斥。
- **轻功文件**：无招式表，改挂 `dodge_msg` 字符串数组（被闪避时显示，见 §6.4）。`valid_enable` 常为 `dodge` 或 `move`。
- **外功文件**：完整模板如 §3。

### 3.3 绝招（perform）文件结构

绝招是独立文件（如 `kungfu/skill/taiji-jian/shenmen.c` 神门十三剑），内容语义：

- 名字 `PNAME`（「神门十三剑」）；
- **多层前置**：相关内功 100 级 + 本武功 140 级 + 基本剑法 125 级 + 内功激发正确 + 内力 > 200 + 体力 > 400（L38-73）；
- 自带一段出手文本（L75："$N运剑如风似电……十三点寒星似乎同时扑出，落点不失厘毫，每一剑都刺向$n手腕'神门穴'！"）；
- 自己做攻防判定与伤害计算（不走普通 round 流程）。
- 获得途径：向掌门"切磋"（qiecuo）解锁，需门派忠诚度（`doc/help/skill` L16-21）。

## 4. 招式命名规律与文本写法（问题 3）

### 4.1 命名规律

1. **四字格为主**，取材古典：
   - 《易经》卦爻辞：降龙十八掌全部招式（亢龙有悔、飞龙在天、潜龙勿用、见龙在田、履霜冰至、神龙摆尾…）
   - 《洛神赋》：凌波微步十式（轻云蔽月、流风回雪、罗袜生尘、惊鸿回眸…）
   - 情绪/意境成语：黯然销魂掌十七招全用失意成语（杞人忧天、无中生有、拖泥带水、呆若木鸡、魂不守舍…）
   - 白话意象：打狗棒法（棒打双犬、拨草寻蛇、天下无狗）
2. **按等级从易到难解锁**，解锁点不均匀（见 §5.2）。
3. 同门武功招式名风格统一（一套武功一个意象系统）。

### 4.2 招式文本模板规律

招式文本 = `$N` 动作铺陈（1-2 句古白话，常含一个"示弱/蓄势"转折）+ 颜色高亮的「招式名」+ 落点指向 `$n` 的 `$l`。槽位约定（`adm/daemons/combatd.c` L312-323、L621-632）：

| 槽位 | 含义 |
|---|---|
| `$N` / `$n` | 攻击者 / 防御者名字（大写=主动方） |
| `$P` / `$p` | 攻击者 / 防御者的"你/他"代词（`= $N`） |
| `$w` / `$W` | 攻击者兵器 / 防御者兵器（无兵器时替换为"拳脚"或"手指"） |
| `$l` | 被击肢体（从防御者 limbs 表随机取，人类 21 个部位，见 §6.7） |

## 5. 等级/品阶/成长结构（问题 4）

### 5.1 数值等级与中文品阶

技能等级是无上限整数（实战常见 0~300+，基本武功经验增长被引擎限制到 300，`combatd.c` L371/434/608）。显示时按等级除以固定步长映射为 **50 档中文品阶**（`cmds/skill/skills.c` L10-21，从低到高）：

> 不堪一击 → 毫不足虑 → 不足挂齿 → 初学乍练 → 勉勉强强 → 初窥门径 → 初出茅庐 → 略知一二 → 普普通通 → 平平淡淡 → 平淡无奇 → 粗通皮毛 → 半生不熟 → 马马虎虎 → 略有小成 → 已有小成 → 鹤立鸡群 → 驾轻就熟 → 青出于蓝 → 融会贯通 → 心领神会 → 炉火纯青 → 了然于胸 → 略有大成 → 已有大成 → 豁然贯通 → 出类拔萃 → 无可匹敌 → 技冠群雄 → 神乎其技 → 出神入化 → 非同凡响 → 傲视群雄 → 登峰造极 → 无与伦比 → 所向披靡 → 一代宗师 → 精深奥妙 → 神功盖世 → 举世无双 → 惊世骇俗 → 撼天动地 → 震古铄今 → 超凡入圣 → 威镇寰宇 → 空前绝后 → 天人合一 → 深藏不露 → 深不可测 → 返璞归真

知识技能另有独立的 **16 档**品阶表（同文件 L23-28：新学乍用 → 初窥门径 → … → 空前绝后）。

### 5.2 招式解锁序列（成长曲线的内容表达）

招式按武功等级逐档解锁，高档间距拉大。黯然销魂掌 17 招解锁点（`anran-zhang.c` 各项 lvl）：
`0, 10, 20, 30, 40, 60, 70, 80, 100, 110, 120, 140, 150, 160, 170, 180, 200`
——前期 10 级一招，后期 20 级一招，"越练越慢"。

### 5.3 成长途径与门槛

- **learn（向师傅学）**：耗潜能（potential），受 `valid_learn` 门禁（师承/先修/内力/姿势/天赋）。
- **practice（自行练）**：每次扣 qi 30-50 与 neili 10-50（`anran-zhang.c` L110-121）。
- **实战成长**：战斗引擎在成功闪避/招架/命中时给少量 combat_exp 与技能点（`combatd.c` L366-380、L429-436、L598-617），基本武功上限 300。
- **能力-数值耦合**：内力保有上限 = 基本内功级别×15，激发特殊内功后 = 内功有效级别×10（`doc/help/neigong` L30-36）。
- **天赋门槛**：降龙十八掌"演练合成"要求 str≥25、con≥20、基本内功 300（`xianglong-zhang.c` L80-99），且"无性"者不可练。

## 6. 战斗文本模板（问题 5）

核心引擎 `adm/daemons/combatd.c` 的 `do_attack()`（L254-741）流程与文本产出顺序：

**出招文本** → 判定躲避（AP vs DP 掷骰）→【闪避文本】→ 判定招架（AP vs PP）→【招架文本】→ 命中 →【命中附加文本（内功/武功 hit_ob）】+【伤害分档文本】→【伤势状态描述】。

一次攻击的可见输出是"招式文本 + 结果实文本"的拼接（result 累加后统一做槽位替换，L621-636）。

### 6.1 出招文本

即武功文件 action 表的文本（§4.2）。第二击时前缀"紧跟着"（combatd.c L303）。

### 6.2 伤害分档文本（damage_msg）

按 `damage_type` × 伤害数值双维度选模板（`combatd.c` L64-133）。伤害类型五组，各组 6-9 档，阈值 10/20/40/80/120/160/240：

- **割伤/擦伤/劈伤**（利器）："结果只是轻轻地划破$p的皮肉" → "在$p$l划出一道细长血痕" → "「嗤」一声划出一道伤口！" → "血淋淋的伤口" → "溅得$N满脸鲜血" → "$w已在$p$l划出一道深及见骨的可怕伤口！！"
- **刺伤**："刺破皮肉" → "创口" → "刺入寸许" → "刺进…不由自主地退了几步" → "血窟窿" → "对穿而出，鲜血溅得满地！！"
- **瘀伤/挫伤**（钝击）："轻轻地碰到，比拍苍蝇稍微重了点" → "瘀青" → "肿了一块老高" → "闷哼了一声" → "「砰」地一声退了两步" → "连退好几步，差一点摔倒" → "吐出一口鲜血" → "像一捆稻草般飞了出去！！"
- **内伤**："打得退了半步，毫发无损" → "痛得弯下腰去" → "脸上一阵青一阵白" → "接连退了好几步" → "吐出一口鲜血" → "气血倒流，鲜血狂喷" → "像滩软泥般塌了下去！！"
- **抓伤**："抓破皮肉" → "细长血痕" → "长长的血口" → "满手沾满了鲜血" → "深及见骨"
- **默认兜底**："结果造成轻微的X伤！…造成非常可怕的严重X伤！"（9 档修饰语，L120-131）

规律：**同一结构「结果 + 程度递进的画面」× 数值档位，档位描述从"轻描淡写"到"夸张惨烈"两级跳**（最后档必带双感叹号）。

### 6.3 招架文本（parry_msg）

基本模板 4 条 + 空手 2 条（`kungfu/skill/parry.c` L13-22），另按防御方兵器类型给 11 套专属模板（axe/blade/club/dagger/hammer/hook/spear/staff/stick/sword/whip，L25-92），要点：

- 招架文本以**防御者为主语**（$n），且常含"反击动作"：如剑法招架"手中$W疾点$P右手手腕，迫得$P收招撤回$w"；鞭法"舞出满天鞭影……$P一招击下，有如石沉大海"。
- 高级武器类招架文本会描述"逼迫对手收招"，给招架以画面感而不只是"挡开"。

### 6.4 闪避文本（dodge_msg）

- **基本轻功**：5 条朴素模板（"但是被$p机灵地躲开了""但是$n已有准备，不慌不忙的躲开"，`kungfu/skill/dodge.c` L14-20）。
- **特殊轻功**：约 10 条带本武功招式名的华彩模板，且以防御者为动作主体（`lingboweibu.c` L10-21 全部十式引用洛神赋意象）。**特殊轻功的"人格"完全由这组闪避文本表达**——轻功没有招式表，其内容价值全在闪避文本。

### 6.5 氛围文本（combatd.c）

- **对峙**（guard_msg，L25-31）：5 条"寻找破绽"模板——"$N注视着$n的行动，企图寻找机会出手。"
- **寻仇开场**（catch_hunt_msg，L33-41）：8 条仇恨台词——"$N和$n仇人相见分外眼红，立刻打了起来！"
- **比武收场**（winner_msg，L43-55）：11 条胜负礼仪文本——"承让了！""君子报仇，十年不晚！"（注意一半以胜者口吻、一半以败者口吻）
- **反击/破绽**："$N一击不中，露出了破绽！""$N见$n攻击失误，趁机发动攻击！"（L716/728）
- **双击**："$N双手分使，灵活异常，好象变成了两个人似的！"（L779，左右互搏）

### 6.6 状态描述（血量/体力百分比 → 文案）

- **伤势**（eff_status_msg，L135-148）：11 档，从"看起来气血充盈，并没有受伤"到"有如风中残烛，随时都可能断气"。
- **体力**（status_msg，L150-162）：11 档，从"充满活力，一点也不累"到"已经陷入半昏迷状态"。
- 均以 `( $N描述 )` 括注形式附加在伤害输出之后。

### 6.7 肢体表（$l 槽位取值）

人类默认 21 个部位（`adm/daemons/race/human.c` L41-45）：头顶、颈部、胸口、后心、左肩、右肩、左臂、右臂、左手、右手、两肋、左脸、腰间、小腹、左腿、右腿、右脸、左脚、右脚、左耳、右耳。NPC 按种族自定义（如毒蛇"头部、身体、尾巴"）。

### 6.8 状态效果文本（condition）

异常状态如中毒按周期扣血并输出一句提示（`kungfu/condition/poison.c`：每次 `info["message"]`），状态带 duration 与 damage 两个数值参数。

## 7. 对本作内容设计的启示

> **2026-08-31 标注（superseded）**：本节第 2-4 条（combat-text 四元组、槽位协议、伤害分档文案矩阵整体移植）已被战斗文本定稿取代，以 `docs/adr/0011-combat-text-system.md` 为准：槽位 13 个（`{attacker}` 语法）、模板 = 片段序列、后果词库 5 维分池（伤害类型概念已删除）。第 1 条（武学分类枚举）与第 6 条（结构化前置）已由 `kind` 字段与 `prerequisites` 字段实现，第 5 条（闪避/招架人格）仍有效——闪避独立模板族。

> ⚠️ **2026-09-01 补充（MUD 转向后）**：本节写于放置游戏时期，以下各条的前提已变——
> - 第 1 条的「境界序列（realms）」**已随 ADR-0019 删除**，改由**武功等级 + 实战经验**驱动（xkx 原味），造诣是纯显示层；
> - 第 2 条的「挂机自动出招」前提**已废**（ADR-0016：命令输入是主要 intent 来源），但「招式 = 文本 + 解锁等级 + 效果区间」的四元组结构**仍然成立**，且更适合 MUD；
> - 第 4 条的「境界」改称**造诣**；
> - 第 6 条前置条件中的「境界」改为**武功等级**。
>
> **未受影响**：文本模板与数据分离、伤害分档文案表整体移植、闪避/招架的武功人格、成长门槛用内容语言表达。

对照本作现有 `content/config/`（activities.json、resources.json、settings.json）与 combat-text 规划：

1. **分类骨架可直接借鉴**： 本作 的"境界序列"（realms）相当于 xkx 的内功/品阶线；建议在 config 中建立与 §2.2 对应的**武学分类枚举**（内功/轻功/拳掌/兵刃/身法招架），每个武功条目声明 `martialType` 与可激发用途，保持"引擎零题材词汇、分类只在 content"的既定原则。
2. **招式 = 文本 + 解锁等级 + 效果区间**： xkx 的 action 表结构（`{action, skill_name, lvl}` + dodge/parry/force/damage 四维区间）是极好的 content schema 蓝本。本作 可在 `content/combat-text` 中以同样的"招式名 + 描述模板 + minLevel + 效果权重"四元组建条目，引擎只按等级过滤再随机抽取——这正是放置游戏"挂机自动出招"的内容化表达。
3. **文本模板与数据分离**： xkx 把变量槽位（$N/$n/$w/$l）直接嵌在内容文本里、由引擎统一替换。本作 应固化一套更小的槽位协议（如 `{attacker}` `{defender}` `{move}` `{limb}`），combat-text 只存模板，聚合引擎做替换——与"修饰符聚合引擎 + 带完整语境的事件流"的既定架构吻合。
4. **伤害分档文案表值得整体移植**： §6.2 的"伤害类型 × 数值档位 → 文案"矩阵是战斗反馈的核心资产，本作 可按自己的伤害数值区间重定阈值，但保留"每类型一组递进画面 + 最后一档夸张化"的写法；品阶表（§5.1 的 50 档）可直接映射到境界/武学等级的展示文案，另备一套知识技能的短档表。
5. **闪避/招架也要有"武功人格"**： xkx 特殊轻功的人格全在闪避文本（§6.4）。本作 的 combat-text 规划中应为"闪避""格挡"各设基本模板组 + 按武学条目可覆盖的专属模板组；同时收场文案（winner_msg 的胜败双视角）适合做放置结算的场景点缀。
6. **成长门槛用"内容语言"表达**： xkx 的 valid_learn 提示（"你的玉女心法不熟练，无法练黯然销魂掌"）表明：前置条件描述本身也是内容。本作 的 config 应让每个武功条目携带结构化前置（先修武功、境界、资源），引擎据此生成这类拒绝文案，而不是在引擎里写死。
